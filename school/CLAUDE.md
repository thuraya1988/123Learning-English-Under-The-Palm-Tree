# منظومة ملتقى المعارف — دليل استمرارية النظام

هذا الملف موجّه لأي مطوّر (بشري أو مساعد ذكاء اصطناعي مثل Claude Code) يبدأ العمل على هذا
النظام لأول مرة — سواء كنتِ أنتِ يا ثريا بنفسك، أو أي شخص تستعينين به لاحقًا. الهدف: تقليل
الوقت اللازم لفهم النظام من الصفر إلى أقل ما يمكن.

## ما هو هذا النظام؟

منظومة إدارة وتشغيل مدرسة ملتقى المعارف للتعليم الأساسي (١–٦) في سلطنة عُمان. مبنية بالكامل
خصيصًا لهذه المدرسة (ليست منتجًا عامًا) — الجداول، أسماء المعلمات، وقواعد العمل كلها حقيقية
ومطابقة للواقع الفعلي للمدرسة.

المالكة والمسؤولة الوحيدة عن القرارات: ثريا (مديرة النظام). غير تقنية — أي شرح تقني يجب أن
يُترجم لخطوات عملية بسيطة عند التواصل معها.

## البنية التقنية (Architecture)

- **الواجهة الأمامية (Frontend):** ملفات ثابتة (HTML/CSS/JS عادي، بدون أي إطار عمل مثل
  React) داخل مجلد `school/`. تُخدَّم عبر **GitHub Pages** من فرع `main` في هذا المستودع،
  على النطاق المخصص: `https://play.under-palm-tree.com/school/`.
- **الخلفية (Backend):** دالتا Supabase Edge Functions (Deno/TypeScript):
  - `supabase/functions/multaqa-secure/index.ts` — كل الإجراءات التي تحتاج تسجيل دخول
    موظفة (معلمات، إدارة). المصادقة عبر `multaqa_staff_sessions` (token في localStorage
    بالمتصفح، صالح 12 ساعة).
  - `supabase/functions/multaqa-public/index.ts` — إجراءات عامة لا تحتاج تسجيل دخول
    (أولياء الأمور، الجدول العام، الإعلانات، بوت أريف).
  - مشروع Supabase: `https://dhhwcqczvcbwdwllfcun.supabase.co` (هذا رابط عام وليس سرًا).
- **قاعدة البيانات:** Postgres عبر Supabase. كل الجداول تبدأ بـ `multaqa_` (أكثر من ٤٠
  جدولًا — القائمة الكاملة والحقيقية موجودة في `supabase/migrations/*.sql`، وهي المرجع
  الوحيد الموثوق للمخطط الفعلي، وليس هذا الملف).
- **الإشعارات:** Web Push حقيقي (مفاتيح VAPID مخزّنة في جدول `multaqa_push_config`، وليست
  متغيرات بيئة — يعني تُدار من قاعدة البيانات مباشرة، لا تحتاج إعادة نشر كود لتغييرها).
- **قنوات إضافية:** تكامل واتساب (`school/whatsapp-notify.js`)، بوت "أريف" الذكي
  (`school/aref/`، يستخدم بيانات الجدول الحقيقي عبر `multaqa-public`).

## ⚠️ فجوة مهمة يجب حلّها: نشر تعديلات الخلفية (Backend Deployment)

**لا يوجد أي أتمتة (GitHub Actions أو غيرها) تنشر تعديلات `supabase/functions/*` تلقائيًا.**
لم أجد أي سكربت أو workflow يقوم بذلك في هذا المستودع. معنى هذا: أي تعديل على ملفات
`multaqa-secure/index.ts` أو `multaqa-public/index.ts` يُحفظ في Git، لكنه **لا يعمل فعليًا
على الموقع الحي حتى يُنشَر يدويًا** على Supabase (عبر لوحة تحكم Supabase مباشرة، أو عبر
أمر `supabase functions deploy` من جهاز فيه صلاحية الدخول لحساب Supabase).

**هذا يجب توضيحه والتأكد منه مع ثريا مباشرة:** من الذي ينشر تعديلات الخلفية حاليًا،
وكيف؟ إذا لم تكن هناك طريقة واضحة، فهذه أولوية عالية — لأنها تعني أن أي تعديل خلفية
(كإصلاح خطأ أو ميزة جديدة) قد يبقى "معلّقًا" في الكود دون أن يعمل فعليًا، دون أن يلاحظ
أحد ذلك.

## سير العمل المُتّبع (Workflow) — مهم جدًا لتجنّب أخطاء شائعة

1. **التطوير على فرع منفصل** (عادة باسم يصف المهمة)، ثم:
   `git fetch origin main && git checkout main && git merge origin/main --ff-only`
   (لأن عمليات أخرى — جلسات Claude أخرى، أو ثريا نفسها — قد تدفع مباشرة لفرع `main`
   بالتوازي، فيجب مزامنة أي فرع عمل مع `main` قبل الدمج فيه).
2. **تدرّج تخزين مؤقت (Cache-busting) يدوي إلزامي:** `school/index.html` يحمّل
   `loader.js?v=X`، و`loader.js` بدوره يجلب كل ملفات `ui-*.html` وكل ملفات `.js`
   (`app-services.js?v=Y`، `secure-platform.js?v=Z`، إلخ) بعلامة `?v=` خاصة بكل ملف.
   **أي تعديل على أي ملف يجب أن يرافقه تغيير قيمة `?v=` الخاصة به في `loader.js`، ثم
   تغيير `?v=` الخاص بـ`loader.js` نفسه في `index.html`** — وإلا فمتصفحات الزائرين ستستمر
   بعرض النسخة القديمة من الملف رغم رفع التعديل.
3. **الدمج لفرع `main`** (الذي يُخدَّم فعليًا عبر GitHub Pages)، ثم مزامنة فرع العمل
   مرة أخرى من `main` بعد الدمج.

## فخّ متكرر: تلف النص العربي عند التعديل المباشر

كتابة نص عربي مباشرة داخل بعض أدوات التعديل قد يُدخل أحرف تحكّم اتجاه خفية (bidi control
characters) تُفسد المطابقة أو تُخفي الفرق بصمت. الحل الآمن المُجرَّب طوال هذا المشروع:
كتابة سكربت Python يقرأ الملف، يعمل `content.replace(old, new)` مع `assert` للتأكد من عدد
مرات الاستبدال، ثم فحص الملف الناتج بحثًا عن أحرف Unicode من فئة `Cf` أو ضمن نطاقات التحكم
المعروفة (`U+200E`, `U+200F`, `U+202A`-`U+202E`, `U+2066`-`U+2069`) قبل اعتماد التعديل.

## كيف تستمر هذه المنظومة بدون الاعتماد على شخص واحد

1. **الموقع لن "يتوقف" من تلقاء نفسه.** GitHub Pages وSupabase خدمتان مستضافتان ومستقلتان —
   يستمران بالعمل طالما حسابا GitHub وSupabase (المسجَّلان باسم ثريا: `thuraya1988`) نشطان،
   بلا حاجة لأي تدخل بشري يومي.
2. **الخطر الحقيقي الوحيد هو التطوير المستقبلي**، وليس التشغيل الحالي. الحل: الاستمرار
   باستخدام مساعد برمجة بالذكاء الاصطناعي (كهذه الجلسة بالضبط) عند الحاجة لأي تعديل —
   لا يتطلب توظيف مطوّر دائم، فقط حساب Claude فعّال. أي جلسة جديدة تقرأ هذا الملف أولًا
   ستفهم النظام سريعًا.
3. **تأكدي أنك (وليس أي طرف آخر فقط) تملكين صلاحية إدارية كاملة** على: حساب GitHub، مشروع
   Supabase، وتسجيل النطاق `under-palm-tree.com`. إن لم تكوني متأكدة، هذا أول شيء تتحققين
   منه.
4. كخط أمان إضافي (اختياري وليس عاجلًا): تعرّفي على مطوّر واحد موثوق (ولو بأجر بسيط لكل
   مهمة) يمكنه — بالاستعانة بهذا الملف — تولّي أي تعديل طارئ إذا تعذّر الوصول لمساعد
   الذكاء الاصطناعي لأي سبب.
